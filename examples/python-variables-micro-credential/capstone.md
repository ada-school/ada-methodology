# 🚀 Capstone — *Ship a Small Program with Variables*

The capstone is delivered as [Atom 5](atoms/atom-5-mini-project-capstone.md). This file is the
**grading brief**: what learners submit, how it maps to KSA, and the showcase format.

---

## 🎯 The brief

> Build a short Python program (**~15–30 lines**) that collects inputs, computes something useful
> using variables, and prints a clean, formatted summary with f-strings — then peer-review a
> classmate's program and do a 30–60s showcase.

The point is a **small, correct, readable** program you can explain — not a big one. An entry-level
task is exactly this: take some data, transform it correctly, present it clearly, and talk through
your choices.

---

## 📦 What to submit

- [ ] **The program** — valid PEP 8 `snake_case` names; at least **3 different data types**; at
  least **one type conversion**; output formatted with **f-strings**.
- [ ] **A sample run** — the inputs you gave and the printed output.
- [ ] **A mini-README** (4–6 lines) — what it does, how to run it, one thing you'd improve.
- [ ] **A peer review you gave** — the Atom 5 checklist applied to a classmate's program.

---

## 🎤 Showcase structure (30–60 seconds)

1. **What it does** (10s) — one sentence.
2. **A variable choice** (20s) — a naming/type decision and why.
3. **A bug you hit** (20s) — what the error message said and how you fixed it.
4. **One improvement** (10s) — what you'd add next.

## 🧬 How the capstone maps to KSA

| Capstone element | Evidences | Component |
| ---------------- | --------- | --------- |
| Correct use of types and a conversion | Understands types & casting | 🧠 K-var-concept, K-data-types |
| Valid, readable PEP 8 variable names | Declaring & naming variables | 🛠️ S-declare-assign (L2) |
| Expressions + f-string output that runs | Using/converting/formatting values | 🛠️ S-use-values (L2) |

| Peer review given + improvement applied | Collaboration & reflection | (capstone-5 collaboration) |

## ✅ Grading

Atom-level checks (`knowledge-mini`, `skill`) gate entry to the capstone, which is then scored on
the standard 5-criteria **Assessment Rubric** below (also in [`rubrics.md`](rubrics.md)).

## 📋 Assessment Rubric

Five criteria across four proficiency bands, weighted to **100 points**.

| Criteria | Excellent (100–90%) | Competent (89–80%) | Developing (79–70%) | Initial (69% or less) | Weight |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Relevance (competency alignment)** | Program clearly meets the brief and uses variables meaningfully and purposefully. | Program meets the brief; variable use mostly purposeful. | Program loosely meets the brief; trivial or forced variable use. | Off-target or trivial; brief not met. | **20 pts** |
| **Application of skills** | Names, types, conversion, expressions, f-strings, functions + unit tests all used correctly. | Most used correctly, with minor errors. | Several gaps (e.g. missing conversion, weak names, no tests). | Minimal or incorrect application. | **25 pts** |
| **Problem-solving** | Handles inputs sensibly; bugs found via tests/errors, fixed and explained. | Works on normal input; fixes most issues. | Works partially; some bugs unresolved. | Frequently broken; errors unresolved. | **20 pts** |
| **Clarity & communication** | Clean output + clear mini-README + crisp showcase. | Generally clear output and docs. | Uneven; missing README or unclear output. | Unclear or missing. | **15 pts** |
| **Collaboration & reflection** | Useful peer review given; applied a fix; honest, specific reflection. | Adequate peer review and reflection. | Minimal review / reflection. | None. | **20 pts** |
| **TOTAL** | | | | | **100 pts** |

> **Pass for the badge:** the program runs and meets the brief, Assessment Rubric weighted score
> ≥ 70% (at least *Developing* on every criterion), and the peer review + showcase are completed —
> **verified by an instructor**. See [`skills-map.md`](skills-map.md) for what the badge unlocks.
